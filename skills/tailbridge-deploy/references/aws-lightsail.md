# AWS Lightsail host

The default AWS flow. Use [EC2](aws-ec2.md) instead when the host needs Ubuntu 26.04 (Lightsail offers Debian 13 but no Ubuntu 26.x), arm64 (Lightsail is x86 only), will stay stopped most of the time (Lightsail bills a stopped instance in full), or the user asks for EC2. Debian 13 is a verified compatible platform; see the repository's `docs/INSTALL.md`.

Pass `--profile "$PROFILE" --region "$REGION" --no-cli-pager` from the input's `host` section on every `aws lightsail` command.

1. Confirm the account with `aws sts get-caller-identity`. An opt-in region such as `ap-east-1` must be enabled first (`aws account get-region-opt-status`). The first Lightsail call in a region the account has not used returns `RegionSetupInProgressException` until AWS finishes setting it up; wait and query again instead of switching regions.
2. Query the image and plan at run time. `get-blueprints` must offer an active `debian_13`; never fall back silently to another OS. Choose the smallest `get-bundles` plan that fits: at least 1 GB RAM for one role, 2 GB for control and derp on one host. Record the price and `transferPerMonthInGb`; relayed traffic counts against that allowance. Upgrade later when monitoring shows pressure; do not start oversized.
3. Pick an availability zone with `get-regions --include-availability-zones`. Use an existing Lightsail key pair (`get-key-pairs`) or import the configured public key with `import-key-pair`; never use `create-key-pair` or `download-default-key-pair`, which return a private key.
4. Create with the machine name from the input: `create-instances --instance-names "$NAME" --availability-zone "$ZONE" --blueprint-id debian_13 --bundle-id "$PLAN" --key-pair-name "$KEY_NAME" --user-data "$(sed "s/<machine>/$NAME/" "$SKILL_DIR/assets/first-boot.sh")" --tags key=ManagedBy,value=tailbridge "key=Description,value=$DESCRIPTION"`, with `host.description` and the names and tags from the repository's `docs/NODE_NAMING.md`. Save the request and response. There is no client token: after a timeout query `get-instance --instance-name "$NAME"` first, and never create again under another name.
5. Wait until `get-instance-state` is `running`, then replace the default firewall (TCP 22 and 80 open to all IPv4 and IPv6 sources) with one `put-instance-public-ports` call built from `docs/INSTALL.md` for the host's roles: SSH from `ssh_source_cidrs` only; control TCP 443; derp TCP `DERP_PORT` and UDP 3478 from `0.0.0.0/0` and `::/0`, for example `fromPort=3478,toPort=3478,protocol=udp,cidrs=0.0.0.0/0,ipv6Cidrs=::/0`. The call replaces every rule and drops IPv6 ranges you do not pass; confirm with `get-instance-port-states`.
6. Allocate and attach a static IP (`allocate-static-ip --static-ip-name "$NAME-ip"`, then `attach-static-ip`). It is free while attached and keeps the address across stop and start; point the service A records at it. The instance's IPv6 address is not static, so do not publish AAAA records for it.
7. Read only the host keys: `get-instance-access-details --instance-name "$NAME" --protocol ssh --query 'accessDetails.hostKeys'`. The full response contains a temporary private key that must never be printed or saved. For `debian_13` the list is empty and Lightsail has no console output, so the host key cannot be verified out of band: tell the user, and only with their consent pin the `ssh-keyscan` result on first use (the firewall already limits SSH to their sources), then keep strict checking. The initial SSH user is `admin`. Confirm the first-boot result: `hostname` is the machine name and `sudo sshd -T` shows `permitrootlogin no` and `passwordauthentication no`.
8. Debian 13 may mount `/tmp` as tmpfs (check `findmnt /tmp`). On a 1 or 2 GB host, run the derp installer with `TMPDIR=/var/tmp GOMAXPROCS=1 GOFLAGS=-p=1` so compiling derper does not exhaust memory.

Record in `local/aws/<machine>.yaml`: provider, region, zone, name, bundle, price, transfer allowance, static IP name and address, SSH user, known_hosts path, host key fingerprint and how it was verified.

To upgrade, create a snapshot (`create-instance-snapshot`), create a larger instance from it (`create-instances-from-snapshot`), verify it, stop the old instance and move the static IP; DNS stays unchanged and the services keep their identities. Delete resources only when the user authorizes it: `delete-instance`, then `release-static-ip` (an unattached static IP is billed), and confirm with `get-instance` and `get-static-ip`; then remove its token and DNS records as described in the [DNS reference](dns-tls.md). Never delete key pairs.
