# TailBridge 设计决策

组件与部署结构见 [架构](ARCHITECTURE.md)，安装接口见 [安装与配置](INSTALL.md)。

## 核心选择

| 决策 | 原因 |
| --- | --- |
| Headscale + 官方 Tailscale | 复用现有客户端与协调协议 |
| Headscale 作为唯一登记处 | 节点、策略、路由和 DERP Map 各有权威来源，不另建本机节点清单 |
| 节点通过 REST API 管理，策略和 DERP Map 以文件为准 | 管理 API 共用控制面的 HTTPS 入口；文件校验与重载见[运维](OPERATIONS.md#中继与访问策略) |
| 目标机运行根目录安装器 | 官方包下载、校验和安装集中在目标机，生产与 E2E 使用同一路径 |
| 完整模板放在 `files/`，用 sed 替换 | 安装逻辑与配置分开维护，在目标机写入实际参数 |
| 独立 derper，每个区域一个节点 | 单机和多机采用同一方式，当前不引入区域内 mesh |
| Headplane 可选 | 管理界面与核心连接分离 |
| 初始拒绝，授权和路由另批 | 入网不自动获得访问其他设备或互联网出口的权限 |
| 默认版本在脚本，Go 由维护者更新 | Headscale / Tailscale 可通过参数覆盖，工具链版本固定 |
| 保留身份，配置覆盖需 `--force` | 支持重跑，避免静默清空授权或重新注册 |

## 职责边界

部署方准备 SSH、首次入网凭据、derper 启动参数及配置维护。安装器按角色安装；有 systemd 时启动 control / node，node 等 daemon 就绪后注册。无 systemd 时由调用方启动和注册。derp 角色只交付二进制。

配置模板只初始化单中继；后续多区域在控制面现有 Map 中追加。设备状态由目标机持久化，已注册信息以控制面为准，实际参数和凭据放在目标机或忽略的 `local/`。

控制与中继入口位于 MagicDNS 尾网域之外。独立主机可各自申请证书；同 IP 部署时中继使用其他端口和文件证书。具体参数与端口见 [安装与配置](INSTALL.md)。

## 实现约束

- 安装器使用 POSIX sh、`set -eu`，这是 gox shell 默认 Bash 的项目例外；测试入口用 Bash，统一执行 ShellCheck。
- 所有候选配置先完成替换与覆盖检查，再发布；原生配置和策略校验通过后才能启用或重启服务。
- `--force` 只允许配置覆盖，不清除身份、不自动重新认证。失效或损坏状态保留并报错。
- `--dry-run` 无副作用；离线测试不代替真实组件、服务和网络验收。
